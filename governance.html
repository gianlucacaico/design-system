The standard. The tokens, components and rules, written down so any page can use them.
Gianluca
Approves every change before it goes live, on either site.
Claude sessions
Draft changes, preview them, open a review page, and check the live site after publishing. They may suggest running an agent, but only Gianluca starts one.

How a change goes live

  • Nothing goes live without approval, and approval for one change doesn't carry over to the next.
  • One change per review page, with the current and proposed wording side by side and phone and desktop previews.
  • Check the live site after publishing, not just the code.
  • Every change can be undone by reverting its review page on GitHub.

The drift check

The kit is a copy of the site's styles, so a check compares the two and says when they part ways. It runs from both sides, each reading what the other publishes: this design system reads the site's live stylesheet at the end of every preview, and the site reads this design system's tokens in its health check after every publish. Either side can also run it on a change before it merges.

Compares
Every colour, card art and layout token on the site with the kit, plus the colours in the site's artwork template and pictograms.
Drift
A token differs, or exists on only one side. Fix it before publishing, by updating the kit or asking whether the site is right.
Info
A colour is used but isn't a token yet. That's a to-do list for the kit, not a blocker.

Versions

  • Version 1 only gets changes that can't break a page: new tokens, new components, fixes, and values that follow the site's look.
  • A breaking change becomes version 2, at its own address, and only with Gianluca's approval. Version 1 then stays as it was.
  • The unversioned kit is always the latest. Only this site's own pages rely on it.

Proposing a change

  1. Start on the main site if it changes how something looks. The design system follows.
  2. Name new colours and sizes as tokens, each with a plain-English use.
  3. Match the site's class names for new components, and add each one to the demo with placeholder copy.
  4. Run the preview. It has to pass with no drift.
  5. Open a review page and record any design decision in the log below.
